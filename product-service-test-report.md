## 8. Errors, Root Causes & Fixes Applied

During Phase 4A execution, the following issues were discovered and fixed with minimal, evidence-based code changes:

### 1. Postgres Role Failure in Healthcheck
- **Error**: Container `postgres` marked unhealthy; logs reported `FATAL: role "postgres" does not exist`.
- **Root Cause**: `docker-compose.yml` hardcoded `pg_isready -U postgres` whereas `POSTGRES_USER` was configured as `admin`.
- **Fix**: Updated `docker-compose.yml` healthcheck command to `pg_isready -U ${POSTGRES_USER:-admin}`.

### 2. Missing Liquibase DDL Migration
- **Error**: Liquibase changelog only contained an empty bootstrap comment; tables `categories` and `products` did not exist in Postgres.
- **Root Cause**: DDL changeset was missing from the service codebase.
- **Fix**: Created `db/changelog/ddl/db.changelog-v1.0.0.sql` creating `categories` and `products` tables with identity PKs, foreign keys, constraints, and indexes. Registered via `includeAll: path: ddl` in `db.changelog-master.yaml`.

### 3. Hibernate / PostgreSQL Type Mismatch on `priceUnit`
- **Error**: `SchemaManagementException: wrong column type encountered in column [price_unit]; found [numeric], but expecting [decimal (Types#FLOAT)]`.
- **Root Cause**: `Product.java` had `@Column(name = "price_unit", columnDefinition = "decimal")` while the field was Java `Double`.
- **Fix**: Removed explicit `columnDefinition = "decimal"` on `Product.java` and aligned DDL migration column type to `DOUBLE PRECISION`.

### 4. Null Pointer / Transient Property on Category Hierarchy
- **Error**: Creating a category without a parent yielded `TransientPropertyValueException: object references an unsaved transient instance: Category.parentCategory`.
- **Root Cause**: `CategoryMappingHelper.java` unconditionally constructed an empty `Category` entity with `null` ID when mapping null `parentCategoryDto`.
- **Fix**: Added null-safe checks in `CategoryMappingHelper.java` and `ProductMappingHelper.java` so parent category is only mapped when `parentCategoryDto` and `categoryId` are non-null.

### 5. Role-Based Access Control Enforcement
- **Error**: Admin mutation routes (POST, PUT, DELETE) accepted requests from standard users.
- **Root Cause**: `SecurityConfig.java` in `product-service` lacked `KeycloakRealmRoleConverter` integration and route-level role restrictions.
- **Fix**: Updated `SecurityConfig.java` to inject `KeycloakRealmRoleConverter` via `JwtAuthenticationConverter` and enforce `.hasRole("ADMIN")` on POST, PUT, and DELETE operations.

### 6. Missing Exception Handler for Not Found Scenarios
- **Error**: Requesting non-existent products or categories threw unhandled exceptions resulting in HTTP 500.
- **Root Cause**: `ProductNotFoundException` and `CategoryNotFoundException` were unhandled by any controller advice.
- **Fix**: Created `GlobalExceptionHandler.java` annotated with `@RestControllerAdvice` mapping these exceptions to HTTP 404 with standard `ApiResponse` error codes `PRD-2001` and `PRD-2003`.
